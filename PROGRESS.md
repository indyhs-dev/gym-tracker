The open card is the first exercise with sets left, with an accent border. The rest are rows (name, "2 × 5–12", chevron) under **Up next**. Tapping any row opens it. Ticking off an exercise you tapped open moves on to the next unfinished one *after* it, so skipping a set doesn't bounce you back. Reopening a done exercise keeps it open, without the accent border. An exercise left part-way shows "1 of 2 sets".

- **Sauna tracker (chunk 19, 16 Oct 2026).** Logging and tracking only: no timer and no notifications (the user times rounds on the iPhone Clock app).
  - **Navigation:** originally a 5th tab, **Sauna**. Chunk 20 replaced this with Gym · Sauna sections (see above). Settings has a new **Sauna** screen for the weekly target and removing sample data.
  - **Data:** Dexie **v2** adds one table, `saunaEntries: 'id, date'`. Existing tables are untouched. Each entry is a session or a skip (`kind`).
    - `date` is a "YYYY-MM-DD" calendar day in **Australia/Brisbane** (`SAUNA_TIME_ZONE`). Week maths works on these strings, so it doesn't depend on the device's time zone or daylight saving.
    - Each round stores `plannedMin`, `leftSec` (as entered, so it can be shown that way) and `completedSec` = planned − left. `completedSec` is always recomputed on save, and all stats use it. A blank or zero time left means the round was completed.
  - `settings.sauna = { weeklyTarget: 3, samplesAddedAt }`, filled in by `withDefaults()`.
  - **Backup format v2** includes `saunaEntries`. v1 backups still restore, with no sauna data. Restoring never re-adds the samples.
  - **Logging:** the sheet pre-fills the context and the plan (round count and lengths) from the last session. Bench, temperature and water were removed in chunk 20. Rounds start as Completed and Feel starts blank (it's required). The fast path is three taps: Log sauna → feel → Save. Save is pinned at the bottom of the sheet (new optional `footer` on `Sheet`).
  - **Time left:** the iPhone number pad has no colon, so digits fill from the right like a timer (3, 3, 7 → 3:37). It must be less than the planned time, and seconds must be under 60.
  - **Skips** count towards the weekly target (`sessions + skips ≥ target`), so a skip can't make a week fall short.
    - "Weeks on target" covers the last 8 weeks, from the week of the first entry. This week only counts once it's met.
    - There's no streak counter.
  - **Charts:** sessions per week (last 8 weeks) with skips stacked in grey and a dashed target line. These are new optional `goal` and `extra` props on `WeeklyBars`; the Progress chart is unchanged.
    - The month calendar shows completed days as solid accent, left-early days as an accent ring and skipped days as grey. Shape differs as well as colour, and there's a legend with counts.
    - The feel trend uses the last 20 sessions.
    - Completion rate and the average minutes per round use the same 20 sessions; the average is small, under the rate.
  - **"Ready to step up?"** appears when the last 3 sessions were all on the same plan, every round was completed, feel was ≥ 4 each time, and the oldest of the 3 was within 21 days. These constants are at the top of `src/lib/sauna.ts`.

- **Rest timer (chunk 18, 13 Oct 2026).** The user asked for it after testing at the gym, to stop switching to the iPhone stopwatch between sets. This overrides the brief's "text only, no timer" and adds red and green to the palette (used only by the timer).
  - Each set row in a **live** workout gets a round ✓ button. Tapping it ticks the set (green tick and set number), closes the keyboard and starts the rest timer. "✓ Log" on a ghost row logs the set and does the same. Past sessions and History edits have no ✓ and no timer.
  - The timer is a bar pinned to the bottom of the workout screen. It counts up like a stopwatch. It's **red** ("Rest · Ready in 2:14") until the lower number of the rest guidance has passed, then **green** ("Go · Ready · guide 3–5 min"). ✕ hides it. Tapping ✓ on another set restarts it.
  - The length comes from the existing rest guidance texts (`parseRest` in `src/lib/rest.ts`): warm-up sets use the warm-up text, other sets use their exercise type's text. So editing Settings → Rest guidance also changes the timer. Text with no number falls back to the default for that type.
  - **No data model change.** The timer and the ticks live in localStorage (`gym-log.rest-timer`, `src/lib/restTimer.ts`), not in the database. Time is worked out from a start timestamp, so it stays right when the app is in the background, the phone is locked, or the app is closed and reopened. Finishing or discarding the workout clears it. Ticks are only on this phone and aren't part of backups or exports.
  - No sound or alert when it turns green. iOS doesn't allow vibration, and a home-screen app can't play a sound while it's in the background.

- **Deleting exercises:** only allowed when no template slot (default or alternative) and no session (`exerciseIds` index) uses the exercise. Slot snapshots inside sessions aren't counted; later UI must skip alternative ids that no longer exist.
- **New exercises:** a type must be chosen (it drives the rest text). The weight step defaults to 2.5 and the flags default to off.
- **Settings forms** (exercise editor, rest guidance) use an explicit Save button. The workout screen will autosave.

- **ExercisePicker:** the shared `ExerciseSearch` (search, matching list, "+ Add “…”" when the typed name is new) is built and used by Settings → Exercises. The bottom-sheet wrapper was moved to chunk 3, where it's first used.
- **Templates** (`src/db/templates.ts`, screens under `src/screens/settings/`):
  - The template editor and slot editor **autosave** every change. There's no Save button; you just go back.
  - Clearing a template's name isn't saved. The field goes back to the stored name when you leave it.
  - Every slot change goes through `normaliseSlot`: sets 1–20 and reps 1–100, whole numbers, with max reps never below min.
  - Raising min reps above max pushes max up, and lowering max below min pulls min down.
- **New slots** start at 2 × 8–12 with no warm-up. The slot editor opens straight after you add an exercise so you can set them.
- **Changing a slot's default** to one of its alternatives swaps them, so the old default becomes an alternative. This suits progressions like Knee Raise → L-sit (`withDefault`).
- **The picker hides exercises already in the slot** (the default when changing the default; the default and alternatives when adding an alternative). Hidden names still block creating duplicates.
- **Picker quick-create:** typing a new name in the picker opens the new-exercise form inside the sheet. "Add to library and use" saves it and picks it in one go.
- **Duplicate** adds "Name (copy)" at the end of the list with new ids throughout, and opens it. Deleting a template asks first and never touches past sessions, since they hold their own snapshot.
- **Template order:** the list is in creation order. Reordering templates isn't in the spec, so it isn't built.
- **Slot reorder:** ↑/↓ buttons (48 px) on each slot card, disabled at the ends.
- **Seeding** (`src/db/seed.ts`): `seedIfNeeded()` runs from `main.tsx` on every launch and does nothing once `settings.seededAt` is set.
  - It adds 32 exercises and 3 templates in a single transaction.
  - An exercise that already exists (same name, any case) is reused rather than duplicated, and its flags are left alone.
  - Seed templates are always added after any existing templates, never merged.
  - Deleting a seeded template doesn't bring it back. Restoring a backup (chunk 10) carries `seededAt` with it.
  - Seed data is plain data in `seed.ts`, and nothing else in the app refers to those names.
- **Target lines** (`targetLine` → `joinUnbroken`) use no-break spaces, non-breaking hyphens and word joiners, so they wrap only at the " | " separators. They're display-only; exports should build their own text.
- **Sessions** (`src/db/sessions.ts`):
  - Only one `active` session can exist at a time; `startSession` throws `ActiveSessionError` otherwise.
  - Starting deep-copies the template's slots into `SessionExercise.slot`.
  - `withDerived()` recomputes `exerciseIds` (every exercise in the session, deduplicated) and `updatedAt` on every write.
- **Start date:** the start sheet's date can't be in the future.
  - For today, `startedAt` is now.
  - For a past date, it's that date at the current time of day, as a placeholder until chunk 8 adds manual times.
  - A past-dated session is `active` (a draft) until it's finished, so Today shows "Resume workout · Legs · Fri 9 Oct".
- **This week** runs Monday 00:00 to Sunday 23:59 local time and counts only finished sessions. **Last session** is the finished session with the latest `startedAt`.
- **Discard workout** (shown only on an active session) asks first, then deletes it. It's needed until Finish exists, and is the agreed "discard a workout started by mistake".
- **The workout screen** (`/workout/:id`) is full-screen with no tab bar. "‹ Today" leaves the workout running.
- **Rest text** is "Rest {type text} · warm-ups {warm-up text}". The warm-up part is dropped when the slot's policy is "none"; ad-hoc exercises show both.
- **Set entry** (chunk 6; replaced by the set table in chunk 21):
  - A set row is two lines.
    - Line 1: the label ("W" for warm-ups, otherwise 1, 2, 3… counting working sets only), the Warm-up chip, a note toggle (✎), and delete (✕). Delete needs two taps: the first arms it and it disarms after 3 s.
    - Line 2: weight and reps steppers.
  - The weight column is 1.3× the width of reps. On screens narrower than 360 px (SE, or Display Zoom) weight and reps stack, with small unit labels inside the fields.
- **Number fields** (`NumberField`) save on every keystroke and keep the exact typed text while focused.
  - Weight accepts "," or ".", up to 2 decimals. Reps take whole numbers only.
  - Unusually long values get smaller text instead of clipping.
- **Steppers** (`StepField`) step by the exercise's weight step, or 1 for reps. From empty, + gives one step and − gives 0. They never go below 0.
- **The weight column heading** says "kg", "kg each" (per hand) or "+kg" (bodyweight).
- **Saved values are cleaned:** weight is ≥ 0 and rounded to 2 decimals; reps are whole and ≥ 0. Empty stays `null`. Editing a set never changes its `loggedAt`.
- **Swap** happens by tapping the exercise name (⇄).
  - The picker shows "This slot" (default and alternatives, minus the current one) first, then all exercises, plus create-new.
  - If sets are logged, it asks "Move N sets to X?" and moves them.
  - The slot snapshot stays as it was, so the target line is unchanged.
- **Notes:** the session note sits at the top, there's an exercise note on each card, and set notes are behind ✎. All autosave. The note fields grow with their text (`field-sizing: content`).
- **"+ Add exercise"** adds an ad-hoc exercise (`slot: null`: rest text but no target line) and scrolls to it. Removing an exercise asks first and mentions how many sets will go.
- **Chips** have a 48 px tap area around a 36 px pill.
- **Ghost rows** (chunk 7; removed in chunk 21, along with copy last set and copy previous):
  - `previousSetsFor(exerciseIds, session)` finds, per exercise, the latest *finished* session that started before this one and has sets for it. Other sessions without sets for it are skipped.
  - Ghosts are last time's sets from position `sets.length` onwards. They're dimmed, and their values show as placeholders.
  - Any of these logs a ghost: "✓ Log", typing, −/+ (which starts from the ghost value), or the warm-up chip. The new set takes the ghost's values plus your change.
- **Keeping focus on a ghost row:** each position has a pre-made set id (`ghostIds`). Logged sets and ghosts render as one keyed list, so the row and its input survive the change and the iOS keypad stays up.
  - A `logging` set makes keystrokes typed before the new set arrives update that set instead of adding another.
  - The position's id is replaced once the add finishes.
- **"Copy last set"** copies weight and reps only. It's disabled when there are no sets.
- **"Copy previous session's sets (N)"** shows while ghosts remain and adds them all in one write (`addSets`).
- **"Last time · Sat 10 Oct"** appears above the sets when there's history.
- **Swapping** shows the new exercise's own history (variations never mix).
- **Live or past** (chunk 8): `isLive(session)` means it's `active` and started less than 16 hours ago, so it was started today with the timer running.
  - A past-dated draft started yesterday or earlier at least 24 hours ago, so it isn't live: no timer, "Save" instead of "Finish".
  - A workout left open overnight also stops being live, so there's no runaway timer.
  - This avoids adding a field to the data model.
- **The workout bar** is a sticky top bar: "‹ Today", the live gym timer (m:ss, or h:mm:ss after an hour) or the date for a past draft, and Finish/Save.
  - The timer is its own component, so only it re-renders each second.
- **The Finish / Save sheet** has start and end time inputs on the session's day.
  - If the end is earlier than the start, it's taken as the next day (ran past midnight).
  - Live: end defaults to `suggestedEnd` (latest set `loggedAt`, or now with no sets). Past: end defaults to start + 1 h.
  - The duration preview updates live, and it says how many exercises with no sets will be left out.
- **`finishSession`** sets `finished` and the times, and drops exercises with no sets. Since chunk 9, finishing goes to the new session's detail page, which is the session summary with its duration.
- **History** (chunk 9): finished sessions only, newest first, grouped by month. Each row shows the date (accent), template, exercise names (up to 2 lines) and duration.
  - The Today "Last session" card links to the detail page.
- **Session detail** (`/history/:id`):
  - Date and start–end times.
  - Gym time and set count, with the duration shown as big numbers and small units (shared `Duration` component).
  - The session note, then each exercise's sets ("W"/numbered, `setText`) with set notes and the exercise note.
  - "Edit session" and "Delete session" (asks first).
- **Set text** (`setText`) is like "22.5 × 8". For bodyweight exercises it's "BW" (0) or "BW+10" (added load).
- **Editing** reuses the workout screen whenever `status === 'finished'`:
  - The bar shows "Editing" and Done.
  - `TimesEditor` covers date, start and end. It saves through `setSessionTimes` once all three are set; an end before the start rolls to the next day.
  - Everything else (sets, notes, swap, add/remove exercise, ghosts from sessions *before* this one) works as in a workout.
  - Done drops exercises with no sets and goes back.
- **Backup & export** (chunk 10, Settings → Backup & export):
  - **The iOS tap rule:** Safari only allows sharing and clipboard writes inside the tap itself. So all data is preloaded with `useLiveQuery(readAll)`, and files and text are built synchronously in the click handler.
  - **Saving files** (`saveFile`): on phones (`pointer: coarse` and `canShare` with files) it opens the share sheet, so you can "Save to Files". Elsewhere it downloads.
  - **JSON backup:** `{ format: 'gym-log-backup', version: 1, exportedAt, data: { exercises, templates, sessions, settings } }`. `lastBackupAt` is set only if the share sheet isn't cancelled.
  - **Restore:** `parseBackup` validates the file and rejects anything that isn't a backup, or is newer or damaged, with a readable message.
    - It asks for confirmation, showing the backup's counts, then replaces everything in one transaction.
    - `seededAt` is kept, or set if missing, so seeding never runs on top of a restore.
  - **CSV:** finished sessions only, oldest first. Columns exactly as specified, with a UTF-8 BOM and CRLF line endings.
    - The set number counts every set of that exercise, warm-ups included.
    - Weight is as entered (per hand / added load). Warm-up is "yes" or "no".
  - **Copy for Claude:** From/To dates (default: the last 28 days), a live preview of the text, and a copy button (clipboard, with an `execCommand` fallback).
    - The text is in fixed English formats so it's the same on any device.
    - Format: a header line, a legend line, then per session "Mon 12 Oct 2026 · Torso · 18:00–19:12 (1h 12m)", the session note, and one line per exercise like "- Name (each): W 15×10, 22.5×8 [set note]. Note: …".
- **Deploy** (chunk 11): `.github/workflows/deploy.yml` builds, tests and publishes `dist/` to GitHub Pages on every push to `main` (Node 24).
  - README.md has step-by-step instructions: GitHub CLI via Homebrew, repo, Pages source "GitHub Actions", push. Vercel is given as an alternative.
  - It also covers the iPhone install (Safari → Share → Add to Home Screen) and that the home-screen app's storage is separate from Safari's.
  - Minimum iOS is 16.4 (Vite 8's default build target).
- **Definition of done** (`scripts/dod-check.mjs`): 26 automated checks in real Chrome against the production build. They cover the service worker, seeding, each template, swap, copy last set, ghosts and copy previous, durations, edit past session, JSON and CSV export, wipe and restore, and offline with the server stopped. All pass.
- **Progress tab** (chunk 12):
  - `src/lib/progress.ts` has `isWorkingSet` (not a warm-up, weight entered, reps > 0), `epley`, `exerciseHistory` (one point per finished session: top weight with its reps, best e1RM from sets of 12 reps or fewer, most reps) and `trainedExercises`.
  - The exercise is chosen with a native `<select>`, most recently trained first, and kept in `?exercise=` in the URL.
- **Weighted exercises** show one chart with **Est. 1RM** in the accent and **Top set** in off-white, on the same kg axis (kg each for per-hand).
- **Bodyweight exercises** get two single-series charts, **Most reps** and **Added weight** (the second is hidden if it's never above 0), since two units must never share an axis.
- **Each exercise has a "Sessions" table** under the chart, newest first, with the same numbers.
- **Charts** (`components/charts/TrendChart.tsx`, Recharts):
  - 2 px lines with dots that have a 2 px ring in the card colour, a hairline horizontal grid, and one y axis with headroom.
  - The time-scaled x axis has up to 4 date ticks.
  - The crosshair tooltip lists every series, values first.
  - The legend appears only with two or more series. Line-end value labels appear only when they wouldn't collide.
- **The Progress screen is lazy-loaded** (about 104 KB gzipped) and precached, so it works offline.
- **Palette check** (dataviz validator, dark, card surface): accent against off-white separates well (ΔE 24.2 colour-blind, 26.5 normal; contrast passes).
  - It fails the lightness-band and chroma-floor checks because one series has to be a neutral under the brief's four-colour rule.
  - Covered by the legend, the end labels and the table, so colour is never the only cue.
- **PRs, volume and gym time** (chunk 13):
  - The Progress tab has a segmented control, **By exercise / Overall**, kept in `?view=` in the URL.
  - **By exercise** adds a **Personal records** card: the heaviest set (shown large, with the date) and a table of best reps at each weight (top 10 weights, each with the date it was first done).
    - A record needs strictly more reps, so the first time it was achieved is kept.
    - For bodyweight exercises, "weight" means added weight.
  - **Overall** shows:
    - **Working sets per week:** last 12 weeks, Monday–Sunday, including empty weeks; columns at most 18 px wide with gaps.
    - **Gym time per session:** last 20 sessions, round 15/30-minute ticks (`minuteTicks`), with the average in the subtitle.
    - Each has a "Show as table" (`<details>`).
  - These are computed on the fly in `src/lib/progress.ts` (`exercisePRs`, `weeklyWorkingSets`, `sessionDurations`). Nothing extra is stored.
- **Warm-up helper** (chunk 14, `src/lib/warmup.ts`), shown on exercise cards as "Warm-up · from 25 last time · 10 × 6–10 · 17.5 × 4–8 · 20 × 2–4":
  - The work weight is last session's first working set. (Until chunk 21 today's first working set took over, which made the line appear mid-set and push the rows down.)
  - "Full": 40% × 6–10, then 65% × 4–8, then 75% × 2–4 for compound exercises only. "1 set" and "0–1": a single 65% × 4–8.
  - Each step is rounded to the exercise's weight step. Steps that round to 0, reach the work weight, or repeat the previous weight are dropped.
  - Hidden for bodyweight exercises, ad-hoc exercises (no slot) and the "none" policy, and when editing a finished session (`hints` prop).
  - It's text only; nothing is logged automatically.
- **Progression** (chunk 15, `src/lib/progression.ts`):
  - **"Go up" box:** appears when last session's *first working set* reached the slot's `repMax`.
    - It suggests 5–10% more, rounded to the step and at least +1 step, e.g. "try 27.5 kg each (+5–10%)". With 0 added load (bodyweight) it says "try adding {one step} kg".
    - It's worded "If your form was good", since the app can't judge form.
  - **Top-set line** under the sets during a workout: "↑ beats", "= matches" or "not yet past" last time's top set.
    - The top set is the heaviest working set, with more reps breaking a tie. Heavier wins; at the same weight, more reps wins.
    - Text carries the meaning; colour (accent for beat) is extra.
  - Both show only during a workout (`hints`). The "Go up" box needs a template slot for the rep range; the top-set line works for any exercise with history.
- **Training block** (chunk 16):
  - `settings.block = { startDate: 'YYYY-MM-DD' | null, weekOffAfter: number }`, default `{ null, 12 }`.
  - `withDefaults()` in `settings.ts` fills in any settings fields added later. It's used by `getSettings` and restore, so old settings and backups keep working.
  - `blockStatus` (`src/lib/block.ts`) counts weeks from the start date by calendar date, so clock changes can't shift it.
    - Week 1 is the start date plus 6 days. Weeks 1–2 are break-in. Past `weekOffAfter` a week off is due. A future start counts down in days.
  - **Settings → Training block:** a start date, "Start a new block today", "Stop tracking", and a "Week off reminder: after week N" stepper (1–52, "usually 12–16").
  - **Today** has a block card ("Week 5 · Training block" / "Break-in week"). Once past the limit it gets an accent border and "Past week 12: time to take a week off". It links to the settings screen.
- **Definition-of-done script** (chunk 17): `check:dod` now covers Phase 2 as well (35 checks).
  - The first Torso session is logged as *yesterday* (past-session flow), so the ghost and progression checks don't depend on the time of day the script runs.
  - Phase 2 checks: warm-up line, no "Go up" below the top of the range, top-set "beats", "Go up" after 22.5 × 12, chart lines, PR, overall charts, training block week (also after restore), and Progress charts offline.
- **Backup reminder:** a card on Today when it's been more than 14 days since the last JSON backup. Before the first backup, the 14 days count from the first finished session, so a brand-new app doesn't nag. CSV doesn't reset it.
- **Dates and times** follow the device's locale (`toLocaleDateString` / `toLocaleTimeString`). Durations look like "1h 12m"; on Today, the units are drawn smaller than the numbers.

## Known issues
- **Not yet tested on a real iPhone.** These can only be checked on the device:
  - the share sheet "Save to Files"
  - the clipboard
  - the native date/time pickers
  - the safe-area insets
  - keeping the keypad open when typing into a ghost row (works in Chrome)
  - `field-sizing` on notes (Safari 18.4+; older versions just scroll)
- The Claude app's built-in browser pane can't register service workers. Offline is verified with `npm run check:offline`, which uses the real Chrome, instead.
- While the Claude app's browser pane is hidden it pauses animation frames, so screenshots taken right after a tap can look stale. Measured navigation is 1–6 ms, so the app itself isn't slow.
- Dexie live queries only notice writes made through Dexie. Test data inserted with raw IndexedDB needs a page reload to show.
- npm reports `fsevents` has an unapproved install script. It's an optional macOS file watcher and ships prebuilt, so it's safe to ignore.
